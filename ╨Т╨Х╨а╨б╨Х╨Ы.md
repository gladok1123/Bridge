# Bridge на Vercel — по шагам

Сайт специально устроен так, чтобы на Vercel он заработал без серверов, баз и настроек:
страницы статические, серверная часть — один служебный маршрут `/api/health`.

## 1. Готовим репозиторий

```bash
cd bridge
git init
git add .
git commit -m "Bridge"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/bridge.git
git push -u origin main
```

`.gitignore` уже исключает `node_modules` и `.next`, а `.env.local` не попадёт в репозиторий —
настройки задаются в панели Vercel.

## 1.5. Запуск на своём компьютере (Windows)

Двойной клик по **`start.cmd`** — поставит зависимости (первый раз) и откроет
`http://localhost:3000` в браузере. Проверки — **`check.cmd`**. На macOS и Linux —
`./start.sh` и `./check.sh`. Имена латиницей не случайно: русский текст внутри `.cmd`
Windows читает в своей кодировке и падает на командах вроде «сё:».

## 2. Заводим проект

1. [vercel.com](https://vercel.com) → **Add New… → Project**.
2. Выберите репозиторий `bridge` → **Import**.
3. Framework Preset определится сам (`Next.js`), Build Command и Output Directory менять не нужно.
4. **Environment Variables** — необязательный шаг, но полезный, если у вас есть свой релей:

   | Имя | Пример | Зачем |
   |---|---|---|
   | `NEXT_PUBLIC_RELAY_URL` | `https://ntfy.мойдомен.рф` | свой релей знакомства вместо публичного |
   | `NEXT_PUBLIC_WS_RELAY` | `wss://relay.мойдомен.рф/ws` | полностью свой канал (свой сервер релея) |
   | `NEXT_PUBLIC_STUN` | `stun:stun.l.google.com:19302` | свои STUN-серверы |
   | `NEXT_PUBLIC_TURN` | `turn:turn.мойдомен.рф:3478\|логин\|пароль` | TURN для мобильных сетей и строгих сетей |

   Качество картинки переменными не задаётся — оно выбирается в интерфейсе
   (до 4K и 60 кадров в секунду для показа экрана, отдельно для камеры).

5. **Deploy**. Через минуту сайт будет на `https://ваш-проект.vercel.app` — уже с https,
   а значит камера, микрофон и демонстрация экрана работают сразу.

## 3. Проверяем

* Откройте сайт → «Создать комнату» → скопируйте ссылку-приглашение (`/r/код#k=ключ`).
* Отправьте ссылку второму устройству (телефон, другой браузер) → должны услышать друг друга.
* Если у кого-то тишина: «Настройки → Проверка» покажет причину построчно.

## 4. Свой домен

Project → **Settings → Domains** → добавьте домен и следуйте подсказке (одна запись CNAME или
две A-записи). SSL Vercel выпустит сам.

## 5. Обновления

Обычный `git push` в `main` — Vercel пересоберёт и переключит сайт. Ничего больше делать не нужно.

## Частые вопросы

**Нужен ли сервер для звонков?** Нет. Звонок — прямое соединение между браузерами.
Публичный релей нужен только для знакомства участников; при желании замените его на свой.

**Хранит ли Vercel что-то про звонки?** Нет. У нас нет ни базы данных, ни логов содержимого:
релей живёт вне Vercel, а ключ комнаты в ссылке после «#» на сервер вообще не уходит.

**Ограничение времени у Vercel (serverless) помешает?** Нет, звонок не идёт через функции
Vercel: страница — статика, соединение — P2P.
