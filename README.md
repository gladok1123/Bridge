# Bridge — звонки, демонстрация экрана, доска и чат

Прямые **P2P**-звонки в браузере на Next.js. Звук, видео, чат и доска идут
напрямую между участниками по WebRTC — в середине нет ни сервера, ни облака.
Комнату создаёте вы, ссылку отправляете друзьям, регистрация не нужна.

---

## Что внутри

| Возможность | Как это работает |
|---|---|
| **Звонок** | WebRTC mesh: каждый соединяется с каждым напрямую, «вежливые» переговоры без гонок |
| **Демонстрация экрана** | `getDisplayMedia`, показ разворачивается на всю сцену, качество до **4K при 60 кадрах** и меняется на ходу |
| **Общая доска** | Штрихи в нормализованных координатах, пачки точек по прямому каналу; вошедшему позже уходит снимок |
| **Чат и реакции** | Сообщения и реакции идут по прямому каналу данных; если прямой канал ещё не поднялся — через шифрованный релей |
| **Запись** | Сетка участников и звук собираются на скрытом холсте и скачиваются одним файлом |
| **Кто говорит** | Уровень микрофона считается `AnalyserNode` — у себя и у каждого участника |
| **Замеры** | Пинг, битрейт, потери и тип соединения (`P2P` / `P2P·NAT` / `TURN`) прямо на плитках |
| **Присутствие** | Участники рассылают короткий пульс; пропавших видно через 20–45 секунд, с явной записью в чате |

Компоновка — как в Discord: слева рельса и колонка комнат, в центре сцена и чат,
справа участники. Регистрации нет, аккаунтов нет, ничего не хранится на сервере.

## Качество картинки — как в Discord

Разрешение, кадры и предел битрейта выбираются отдельно для камеры и для показа экрана:

| Что | Варианты |
|---|---|
| Разрешение | 360p · 480p · 720p · 1080p · 1440p · **4K (3840×2160)** |
| Кадры в секунду | 15 · 24 · 30 · **60** |
| Предел битрейта | Авто · 1,5 · 4 · 8 · 15 · 25 · **40 Мбит/с** |
| Оптимизация (для экрана) | Авто · **Резко (текст)** · **Плавно (движение)** |

* «Авто» считает битрейт по размеру кадра и кадрам в секунду: 1080p·60 — около 10 Мбит/с,
  4K·60 упирается в верхние 40 Мбит/с. Ручной предел всегда имеет приоритет.
* **Меняется на ходу.** Качество можно переключить и в настройках, и прямо на плашке
  «Вы показываете экран» во время показа — без остановки и перезапуска звонка.
* **Ничего не растягивается.** Если монитор меньше выбранного разрешения, отдаётся как есть;
  если больше — картинка уменьшается перед отправкой (`scaleResolutionDownBy`), а сам захват
  перестраивается через `applyConstraints`, чтобы не гнать лишние пиксели по сети.
* «Резко (текст)» ставит дорожке `contentHint = 'text'` и приоритет резкости — для кода,
  презентаций и таблиц. «Плавно» — для видео и игр.

## Как соединяются участники

```
браузер A ──── зашифрованные SDP/ICE ────► релей знакомства ◄──── зашифрованные SDP/ICE ──── браузер B
    │                                                                                          │
    └──────────────────  звук · видео · чат · доска — напрямую (WebRTC)  ──────────────────────┘
```

* **Релей знакомства** передаёт только «кто в комнате» и параметры соединения. Имя комнаты
  на нём не видно (только хеш), содержимое — запечатано AES-GCM ключом из ссылки.
* По умолчанию используется публичный релей `https://ntfy.sh` (SSE + POST). Своего сервера
  для звонка не требуется, и это удобно для Vercel.
* Нужен полностью автономный контур — поднимите свой релей: `npm run relay`
  (чистый Node.js, без зависимостей) и укажите его в настройках или в `NEXT_PUBLIC_WS_RELAY`.
  Если свой релей недоступен, канал сам возвращается к публичному.

### Ключ комнаты

Ссылка-приглашение выглядит так: `/r/код#k=ключ`. Часть адреса после «#» **не отправляется
на сервер** — ключ живёт только у участников. Отпечаток ключа (10 знаков) показан в шапке
комнаты: у друзей он должен совпадать. Ссылка без ключа тоже работает, но тогда участники
не расшифруют кадры друг друга — поэтому пересылайте именно ссылку целиком.

## Быстрый старт

```bash
npm install
npm run dev            # http://localhost:3000
```

На Windows проще ярлыками в корне проекта: **`start.cmd`** — запуск (при первом запуске
сам поставит зависимости), **`check.cmd`** — все проверки. На macOS/Linux — `./start.sh`
и `./check.sh`. Имена и текст ярлыков латиницей специально: русские буквы внутри `.cmd`
Windows читает в своей кодировке и ругается на команды вроде «сё:».

> Камера и микрофон браузеры дают только на **https** или на **localhost**. Открывайте
> `http://localhost:3000` у себя — или разверните на Vercel, там https сразу.

Проверки — одной командой:

```bash
npm run check                # всё сразу: сборка + логика + релей + сайт в поддельном браузере
npm test                     # 106 проверок: комната, доска, шифрование, качество, релей
npm run test:site            # 285 проверок: сайт целиком в поддельном браузере
```

Проверки сборки и сайта требуют `esbuild` и `jsdom` — они в `devDependencies`, то есть
достаточно обычного `npm install`. Если их нет, `npm run check` скажет об этом прямо.

## Деплой на Vercel

1. Залейте папку проекта в свой Git-репозиторий (GitHub/GitLab/Bitbucket).
2. На [vercel.com](https://vercel.com) → **Add New → Project** → выберите репозиторий.
   Vercel сам поймёт, что это Next.js: никаких настроек сборки менять не нужно.
3. Переменные окружения (Project → Settings → Environment Variables) — **все необязательные**:

   | Переменная | Зачем |
   |---|---|
   | `NEXT_PUBLIC_RELAY_URL` | Свой релей знакомства вместо `https://ntfy.sh` |
   | `NEXT_PUBLIC_WS_RELAY` | Адрес своего WebSocket-релея (`wss://…/ws`) |
   | `NEXT_PUBLIC_STUN` | Свои STUN-серверы через запятую |
   | `NEXT_PUBLIC_TURN` | TURN для строгих сетей: `turn:хост:3478\|логин\|пароль` |

4. Deploy. Сайт готов: страницы статические, серверная часть — один служебный маршрут
   `/api/health`. Никаких баз данных и фоновых процессов не требуется.

> Если хочется совсем без внешних сервисов: поднимите `npm run relay` на любом своём
> компьютере или VPS и укажите `wss://ваш-адрес/ws` в `NEXT_PUBLIC_WS_RELAY`.

## Свой релей

```bash
npm run relay            # слушает 0.0.0.0:8080, проверка: curl localhost:8080/health
```

Он раздаёт зашифрованные кадры участникам одной комнаты, ничего не расшифровывает и не хранит.
Для доступа по https поставьте перед ним обратный прокси (Caddy достаточно одной строкой).

## Горячие клавиши

`M` микрофон · `V` камера · `S` показ экрана · `H` рука · `B` доска · `R` запись ·
`U` участники · `C` размер чата · `Esc` закрыть окно · `/` перейти к вводу комнаты.

## Структура

```
app/                    маршруты Next: главная, комната /r/[code], /api/health
src/lib/                утилиты, шифрование (crypto.js), транспорт релея (relay.js), иконки
src/core/               ядро без React: доска, состояние комнаты, WebRTC-сетка, медиа, запись,
                        проверка связи
src/hooks/useBridge.js  рантайм: соединяет ядро, сеть и состояние React
src/components/         интерфейс: рельса, комнаты, сцена, чат, участники, доска, окна
relay/server.js         свой релей сигналинга (Node, без зависимостей)
tools/                  проверки: unit.mjs, smoke.mjs, check-all.mjs, поддельный браузер
```

## Что было сделано в этой версии

* Интерфейс переделан под Discord: рельса, колонка комнат, сцена, чат, участники, полоса голоса.
* **Никаких упоминаний сторонних платформ и сервисов** — только свои механизмы.
* Все соединения — прямые (P2P). Посторонний сервер видит только шифрованный обмен знакомством.
* Починены демонстрация экрана и передача звука: скрытые `<audio>`-элементы для чужого голоса,
  честные состояния «включено/недоступно», отдельная дорожка для показа экрана.
* Найдено и исправлено проверками: канал данных не подключался при создании соединения
  (обработчики вешались до регистрации участника), падение при рисовании на доске,
  потеря потока показа экрана при смене качества.
* Качество картинки доведено до 4K·60 с отдельными настройками для камеры и показа экрана
  и мгновенным переключением прямо во время показа.
* Главная страница: вход по коду или ссылке, свои комнаты с ключами, проверка связи, шаги.
